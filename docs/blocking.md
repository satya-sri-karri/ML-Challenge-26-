# Blocking Module — Documentation & Usage Guide

**Owned by:** Person B  
**Branch:** `feature/blocking`  

---

## 1. What It Does

`src/blocking/` generates high-probability candidate entity pairs between Source 1 (reference source) and the target sources (Source 2 and Source 3) before pairwise feature engineering and classification.

To eliminate the intractable $O(N_1 \times (N_2 + N_3))$ search space (over $12.5$ million records / $23$ trillion comparisons) on consumer hardware, candidate generation uses **sub-quadratic multi-signal inverted indexing** with strict block-size frequency capping.

Candidate pairs are generated by **unioning** multiple cheap, independent signals:
1. **Name Signal:** Exact `name_core`, cleaned domain names (`aristosteel.com` $\rightarrow$ `aristosteel`), distinctive token inverted index, and 3-character prefixes.
2. **Address Signal:** Compound numeric + distinctive location tokens (e.g. `85_ticonderoga`), sorted location token pairs (`guthrie_surprise`), with graceful handling of empty addresses (~3.3% in target sources).

Downstream stages (Person C's Stage-A GBDT and Person D's Stage-B LLM verification) evaluate similarity only on this candidate set.

## 2. Quick Start

### Python API

```python
import pandas as pd
from src.normalization.normalizer import normalize_source
from src.blocking.blocker import generate_candidates, generate_candidates_multi_source

# 1. Normalize sources (via Person A's module)
s1_norm = normalize_source(s1_df, "source1")
s2_norm = normalize_source(s2_df, "source2")
s3_norm = normalize_source(s3_df, "source3")

# 2. Generate candidates against a single target source
candidates_df = generate_candidates(s1_norm, s2_norm)

# 3. Or generate unified candidates across both Source 2 and Source 3
candidate_map = generate_candidates_multi_source(
    s1_norm,
    {"source2": s2_norm, "source3": s3_norm},
    max_prefix_block_size=1000,
    max_token_block_size=500,
    max_addr_block_size=500,
)
# Returns: dict[str, list[str]] mapping source1_entity_id -> list of candidate IDs
```

### CLI Script (`scripts/run_blocking.py`)

Generate `output/candidate_pairs.tsv` directly from dataset files:

```bash
# Using dataset directory
python scripts/run_blocking.py --dataset-dir /path/to/dataset --split train

# Or using explicit paths (TSV or Parquet)
python scripts/run_blocking.py \
    --source1 /path/to/train_source1.tsv \
    --source2 /path/to/train_source2.tsv \
    --source3 /path/to/train_source3.tsv \
    --ground-truth /path/to/train_ground_truth.tsv \
    --output output/candidate_pairs.tsv \
    --report reports/blocking_recall_report.md
```

## 3. Candidate Output Formats

### DataFrame Interface (`generate_candidates`)
Returns a `pd.DataFrame` with columns:
- `source1_index`: Integer positional index in `source1`
- `source2_index`: Integer positional index in `source2`
- `source1_entity_id`: e.g. `S1-10001`
- `source2_entity_id`: e.g. `S2-20005`

Deduplicated by `(source1_index, source2_index)`.

### Submission TSV Format (`candidate_pairs.tsv`)
Produced by `write_candidate_pairs_tsv()` or `scripts/run_blocking.py`:
- **Header:** `source1_entity_id\tcandidate_entity_ids`
- **Rows:** Exactly **one row per Source 1 entity**, sorted/preserved in order.
- **Candidate IDs:** Comma-separated list of target entity IDs (combining S2 and S3), e.g.:
  ```tsv
  source1_entity_id	candidate_entity_ids
  S1-925783039	S2-166376419,S3-202863386
  S1-773889195	
  S1-377745466	S2-764573417
  ```
- **Singletons:** Zero candidates produce an empty string after the tab (`S1-773889195\t`).
- **Deduplication:** No duplicate candidate IDs within a row.

## 4. Multi-Signal Blocking Strategy

Real noise patterns observed in `reports/eda_summary.md` dictate that name and address signals must be **OR-combined (unioned)**, never AND-gated:

### A. Name Blocking Keys
1. **Exact Core Name**: Matches identical normalized names (`name:{name_core}`).
2. **Domain-Cleaned Name**: Strips TLDs for domain-style names (`aristosteel.com` $\rightarrow$ `aristosteel`), matching with non-domain references.
3. **Distinctive Token Inverted Index**:
   - Indexes non-generic tokens ($\ge 3$ characters) from `name_tokens`.
   - Filters out `NAME_STOPWORDS` (e.g. `inc`, `ltd`, `services`, `enterprises`, `holdings`).
   - Prunes tokens whose target block size exceeds `max_token_block_size = 500`.
4. **3-Character Prefix**: Captures minor character typos and truncations. Strictly pruned if block size exceeds `max_prefix_block_size = 1000`.
5. **Transliterated ASCII Tokens**: Fallback for non-ASCII Indian script names.

### B. Address Blocking Keys
1. **Compound Number + Token Keys (`addr_num_tok:{number}_{word}`)**:
   - Combines house/street numbers from `address_numbers` with non-stopword location words from `address_tokens` (e.g. `85_ticonderoga`, `17437_surprise`).
   - Extremely selective: while house number `85` matches thousands of buildings nationwide, `85_ticonderoga` matches only $1\text{--}2$ entities.
   - Crucially recovers pairs where **names are completely unrelated** (e.g. `Dréxkor` $\leftrightarrow$ `Atlantic`).
2. **Sorted Distinctive Token Pairs (`addr_pair:{tok1}_{tok2}`)**:
   - Alphabetically sorted pairs of location tokens (e.g. `guthrie_surprise`).
   - Robust to **scrambled address field ordering** (e.g. state-first, number-last).
3. **Empty Address Route**:
   - For records where `address_is_empty` is `True` (~3.3% of Source 2/3), zero address keys are generated. They are safely routed through the name blocking path without crashing.

## 5. Metrics & Validation

### Key Functions
- `measure_candidate_volume(candidates)`: Returns total pairs, unique S1/S2 entities, and average candidates per S1 entity.
- `measure_blocking_recall(candidates, ground_truth)`: Computes recovered true pairs vs total true pairs.
- `evaluate_blocking_metrics(candidate_map, ground_truth, total_s1, total_targets)`: Computes recall ceiling and reduction ratio:
  $$\text{Recall Ceiling} = \frac{\text{Recovered True Pairs}}{\text{Total True Pairs}}$$
  $$\text{Reduction Ratio} = 1 - \frac{\text{Candidates Generated}}{\text{Total Possible Pairs}}$$
- `measure_blocking_performance(source1, source2)`: Measures execution runtime and peak Python memory (`tracemalloc`).

### Empirical Benchmark Performance (Held-out 20% Split)
- **Recall Ceiling:** **100.00%** on held-out validation split.
- **Reduction Ratio:** **92.49%** on held-out validation split.
- **Runtime:** $\approx 1.8\text{s}$ per 1k S1 entities vs 3.5k targets.
- **Signal Ablation:** Name-only achieves 89.67% recall; Address-only achieves 95.57%; the Multi-Signal Union achieves 100.00%.

See `reports/blocking_recall_report.md` for the full empirical report and ablation study.

## 6. Assumptions & Limitations

### Assumptions
- Inputs are normalized by `src/normalization/` prior to blocking (or raw TSVs normalized on-the-fly by `scripts/run_blocking.py`).
- Blocking does not filter or gate on `country` values, ensuring zero degradation on unseen test countries (e.g. France).
- Downstream Stage-A ML (Person C) performs pairwise feature calculation and scoring on the generated candidates.

### Limitations
- Keys with block size $> \text{threshold}$ are pruned for memory safety. Extremely common words (e.g. "Services", "Main St") are deliberately dropped from inverted indexes.
- Dataset paths are provided by the caller; no local paths or OS usernames are hard-coded.
